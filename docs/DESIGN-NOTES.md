# CET-6 Study Companion · 设计取舍与开发记录

> 这是项目首页（[README](../README.md)）背后的那一份：每一轮改了什么、为什么这么改、
> 哪些硬规则不许破。**想了解产品怎么用，看 README；想了解为什么这么做，看这里。**

面向中国大学生的六级备考督学系统。

**第七轮：Plan 页改成滑动式周视图 —— 一天一屏、+ 自定义任务、真题任务可计时完成、全做完发打卡卡。**

本地优先（IndexedDB），无需登录，数据只存在这台设备上，可随时导出 JSON 备份。

## 快速开始

> 项目内置了一个工作区本地的 Node 工具链（`.toolchain/node24`），不需要全局安装 Node。

```bash
export PATH="$PWD/.toolchain/node24/bin:$PATH"

npm run dev        # 开发服务器
npm run build      # 生产构建
npm start          # 运行生产构建
npm run check      # typecheck + lint + 业务规则校验 + 真题数据校验
npm run verify       # 全部校验（3606 + 441 + 26 + 90 项）
npm run verify:papers # 只跑真题数据校验（441 项）
npm run verify:vocab   # 生词本写入路径校验（26 项，跑在内存 IndexedDB 上）
npm run verify:plan    # 计划模块落库校验（90 项，也跑在内存 IndexedDB 上）
```

技术栈：Next.js 16（App Router）· React 19 · TypeScript · Tailwind CSS v4 · Dexie · lucide-react · Motion。

## 第三轮：三条硬规则

这三条决定了本轮几乎所有设计决策。

### 1. 任务不估时间，按模块算

给每个任务写"大概 30 分钟"，等于让学生每天做一道算术题；做不完就会有挫败感。
所以计划里**没有分钟、没有小时**，档位文案里也没有：

| 档位 | 标语 | 每周额度 | 实际安排 | 真题槽位 |
| --- | --- | --- | --- | --- |
| L1 忙碌期 | 先保住节奏 | 18 个模块 | 15 | 2 个（都是片段，不排写作翻译）|
| L2 常规期 | 覆盖听读写 | 30 个模块 | 24 | 3 个 |
| L3 加强期 | 把真题吃透 | 38 个模块 | 32 | 4 个 |
| L4 决战期 | 按考场节奏跑 | 52 个模块 | 43 | 5 个 |

- "模块"只用于**内部限流与排序**，UI 永远不把它换算成时间展示。
- 统计口径同步改掉：今天是"完成了 N 个模块"，不是"学习了 N 分钟"。
- `DailyTask.minutes` / `actualMinutes`、`StudyLog.minutes`、`PlanVersion.budgetMinutes` 全部移除，
  换成 `units` / `weeklyUnits` / `extraUnits`（`src/lib/types.ts`）。
- Dexie 升到 **v3**，带真实的数据迁移：老任务补 `units = 1`，老计划补 `weeklyUnits`，
  老作答记录补 `sessions`。`minutes → units` 没有可信的换算关系，所以不做换算，直接丢掉那个估算值。

### 2. 真题按真实考场时长掐表

四个时长直接抄自试卷卷面每个 Part 的 Directions 标题，不是估算：

| Part | 官方时长 |
| --- | --- |
| Part I · Writing | 30 分钟 |
| Part II · Listening Comprehension | 30 分钟 |
| Part III · Reading Comprehension | **40 分钟** |
| Part IV · Translation | 30 分钟 |

全卷 130 分钟。定义在 `src/lib/papers/exam-clock.ts`，`scripts/verify.ts` 逐条断言。

- 每个 Part 一份计时，**跨题段共享**：听力第 1 段和第 5 段共用那 30 分钟，阅读四个题段共用那 40 分钟。
- 点「开考」只记录起点，**不猜任何时长**；剩余时间来自用户真实的开考时刻。
- 交卷时记录**真实用掉的秒数**，页面显示"实际用了 N 分 M 秒 / 比考场少 X 分钟"。
- 最后 60 秒倒计时转珊瑚色；时间到提示可以交卷。

### 3. 沉浸模式：先全英文做题，交卷才给解析

真实考场不给中途看答案，所以解锁条件是**交卷**这一个显式动作，不是逐题"看解析"按钮。

交卷前**不渲染**：解析、题干译文、选项中文、听力原文、解析册生词、范文、参考译文、译点精析。
交卷后一次性解锁该 Part 全部题目的解析。

> 这里的「生词」指解析册里随卷附的生词表，和第四轮的**生词本**是两回事：
> 前者是原书资料（交卷前不给），后者是学生自己记的（做题时就能记，只是记进本子、不给答案）。

## 第四轮：听力怎么练，生词怎么留

### 1. 听力不显示题干，只给 A/B/C/D

真实的听力练习本来就是先扫选项、知道待会儿要听什么，再听音频定位。
所以听力页**不渲染题干**，只显示四个选项和一句提示「只看选项，听音频作答。」

这个改法有个硬前提：**每道听力题都必须有完整的 A–D 四个选项**，
否则"先看选项"根本无从谈起。所以它不是一条 UI 约定，而是一条断言——
`scripts/verify.ts` 第 2b 节逐题检查 25 道听力题的四选项齐全，缺一即失败。

阅读页不受影响，题干照常显示（阅读本来就是看着题干找依据）。

### 2. 听力的中文解析默认折叠

交卷后立刻把中文解析摊开，等于把答案直接递到手边。所以听力页的解析分两层：

- **英文依据句**直接可见 —— 依据是英文材料本身，不算泄露答案。
- **中文解析**收在「**看中文解析**」按钮后，想看再点开。

只做听力，是因为这正是用户提的场景。阅读页的解析保持交卷后直显；
真要统一，折叠开关在 `QuestionBlock` 的 `collapseExplain` 上，改一个传参即可。

### 3. 生词本

听力、阅读页的每道题都有「**记生词**」入口。点开后从该题的英文文本里提取候选词，
点一个词就填进面板，可以顺手写释义和备注（都可留空），保存后进生词本 `/vocab`。

几个刻意的取舍：

- **不做分词器。** 候选词用「长度 ≥ 8 + 停用词表」筛，宁可少给也不给错候选——
  简易分词会吐出 `He`、`which` 这种根本不是生词的东西，反而污染生词本。
- **重复记同一个词只合并，不新增。** `mergeVocabEntry` 只补空缺，
  **绝不覆盖学生自己写的释义和备注**，不重置 `reviewCount`，出处保留最早记的那次。
  抽成纯函数放在 `src/lib/vocab.ts`，六条断言逐条守死。
- **回原题的链接是反查出来的，不是猜的。** `questionHref` / `sentenceHref`
  按题号和句子 id 回题库定位真实题段；猜 id 会跳到错的段落，比不给链接更糟。
- **复习是翻卡式的。** 生词本支持搜索、按「全部 / 没复习过」筛选、点「复习一次」计数、
  改释义、移除，以及整本翻卡复习。

数据存 IndexedDB 的 `vocab` 表（Dexie **v4**），跟着 JSON 备份一起导出导入。

### 4. 顺手修掉的毛病

- **用时文案自相矛盾**：曾出现「实际用了 1 分钟 / 比考场少 30 分钟」。新增 `elapsedLabel`，
  不足一分钟直接给秒数；不足一分钟时那句对比语不出现。
- **写作 / 翻译页的「已答 0/200」**是错的计数（草稿按字符算的），改为 `showCount` 关掉。
- **`useEnsureWeeks` 静默吞错**：生成失败会 `console.error`，不再让整周任务停在旧模板上却毫无异常。
- **`pickActiveTasks` 并列排序不确定**：排序键改为 `effectiveFrom` + `createdAt` 两级。

## 第五轮：核心词库

用户提供了《六级核心词汇》上册（80 页）与下册（16 页）两份 PDF 原件，解析后接进生词本。

### 为什么不把 374 条直接灌进生词本

生词本是"**我自己不认识的词**"的笔记本。书里的 374 条全灌进去，它就变成一本词典，
复习时根本分不出哪些是真欠的 —— 而复习是生词本唯一的功能。

所以书里的内容做成一层**可搜、可筛的词库**，看到真的不会的再点「收进生词本」。
`/vocab` 顶部切成两个标签：**我的生词** / **核心词库**。

### 数据从 PDF 怎么来的

`scripts/parse-wordbooks.py` 从 PDF 抽取文字后按版式解析，产出 `src/lib/wordbooks.data.ts`
（自动生成，勿手改）。两册版式完全不同，所以走两条解析路径：

| | 结构 | 解析结果 |
| --- | --- | --- |
| 上册 | `Unit N 主题` 下的词条 | **103 词**，跨 10 个 Unit（16/8/11/9/12/7/10/6/13/11）|
| 下册 | `专题 N` 下的同义替换 | **271 条**，跨 5 个专题（14/3/54/100/100）|

下册内部还有三种版式：专题 1 用 `#原因#` 分组 + `①` 条目号，专题 2 用 `①观点词（动词）【认为】` 分组，
专题 3 是扁平等号链，专题 4/5 是编号清单。解析器按专题逐个判定版式，不靠猜。

每条上册词条带：词性、**音标**、中文释义（多词性全收）、派生词 / 近义词 / 反义词 / 词组 / 拓展词。
47 条有近义词，11 条有反义词，80 条有词组，72 条有派生词。

### 三个刻意的取舍

- **【例】真题例句和右栏详解没有导入。** 双栏排版下译文会串行，逐句对齐不可靠。
  和"不伪造时间戳"是同一条底线：**宁可少导，也不导错位的释义。**
- **修掉了 PDF 字体带来的部首兼容字。** 原件里 `⽀持` `⻜⾏` `有偏⻅的` 用的是
  CJK 部首补充区的变体字（U+2EC5 / U+2EDC 等）。NFKC 能修康熙部首，修不了这一区，
  所以做了显式映射（⻅→见、⻛→风、⻜→飞、⺠→民、⻓→长），
  `verify.ts` 有断言守着这些字不许残留在数据里。
- **NFKC 会把 `①②③` 兼容分解成阿拉伯数字**，而它们正是下册的条目号。
  归一化前先用私有区哨兵保护，处理完再还原。

### 收词进生词本时守住既有规则

「收进生词本」走的是**同一条** `addVocabEntry` 通道，所以上一轮的规则全部照旧生效：
同一个词重复收只合并、不新增；不覆盖学生自己写的释义和备注；不重置复习次数。

新增 `VocabEntry.sourceKind`（`"paper" | "wordbook"`）区分出处。旧记录没这个字段，
读侧一律归一成 `"paper"`，不需要升 Dexie 版本。

**词库来源的出处不可点** —— 它没有题号也没有句子 id，硬凑一个 `/papers/wordbook`
只会跳到 404，所以渲染成纯文字。

### 为什么写入路径用脚本验，不用浏览器点

浏览器里点「收进生词本」验证不了：元素坐标在多次查询之间对不上，点击会落到固定底栏上
（实测点「收进生词本」实际点中了 PLAN 导航）。与其跟一个不可信的点击较劲，
不如用 `fake-indexeddb` 把真正要保证的链路跑一遍 ——
`scripts/verify-vocab-store.ts` 26 项覆盖：落库字段、重复收不新增、
学生释义不被覆盖、词库不顶掉真题出处。

### 生词本页面

- **我的生词**：统计卡、搜索、全部/没复习过筛选、词条卡、整本翻卡复习、改释义、移除。
- **核心词库 · 上册**：Unit 筛选（带词数）、搜索（可按中文释义搜）、词条卡
  （音标 + 多词性释义 + 派生/近义/反义/词组折叠区 + 收词按钮，已收的显示「已在生词本」并禁用）。
- **核心词库 · 下册**：专题筛选、同义替换组按彩色 chip 展示同一条链、整条链的意思。

## 第六轮：把词库做成能背的东西

上一轮把两册词书接进来了，但形态还是"列表 + 搜索"，和"背单词"是两件事。
这一轮按不背单词 / 墨墨的用法重做。

### 形态

```
核心词库 → 单元分览 → 一屏一词 → 不认识就收进生词本
```

- **单元分览**：10 个单元卡片，每个带主题、词数和一段简介。不用一次看完 103 个词。
- **翻卡**：一屏一个词，大字词形 + 音标 + 🔊 发音。
  **左右滑动换词**，也支持键盘 ← →；顶部有进度条和 `x / N`。
- **中文开关**：一键把所有中文（释义、词表释义、例句译文）整块藏起来，只留英文。
- **不认识 · 收进生词本**：点一下进生词本，已收的显示「已在生词本」并禁用。
- **例句**：默认折叠，标题上直接写原书出处（如 `2023 年六级仔细阅读`）。
- **下册**：专题筛选 + 同义替换按彩色 chip 展示，原书例题（文章 + 题干 + A–D 选项）折叠保留。

### 这一轮把例句导进来了

上一轮判定「双栏排版下译文会串行，逐句对齐不可靠」而放弃了例句。
这一轮把它解决了，靠的是三件事：

1. **【例】行自带词形**（`【例】economy n.经济`），所以每个例句块能自锚定，
   不依赖"离哪个词条近"这种不可靠的推断。
2. **例句块挂到它前面最近的词条上**，并逐条抽查过归属
   （`prosper` 拿到的是巧克力树那句，不是 `restore` 的）。
3. **译文跨行拼接的判据是"拼完必须收尾"**：双栏把译文截断时，续行紧跟在译文行之后，
   跳过右栏的分组头和详解行就能找到。但如果拼完仍不以 `。！？…` 结尾，
   **宁可丢掉整条译文，也不给半句或者接上别的栏的尾巴**。

最后这条是断言逼出来的：加上校验后立刻抓到 6 处真实串行
（`crisis` 的译文接上了 `短缺的`、`work` 的接上了 `’s capacity,`），全部修掉了。

### 词表改成中英对照

上一轮只拿到了头部那行"光秃秃的词表"（`近义词：currency，financial，monetary`）。
这一轮把右栏的详解也解析了 —— 那里有音标和中文：

```
近义词：
currency ['kʌr(ə)nsɪ] n.货币
financial [faɪ'nænʃ(ə)l] adj.经济的，金融的，财务的
```

**966 条词表条目，909 条带中文（94%）**。同一个词两份数据时保留更全的那份。
翻卡上派生词 / 近义词 / 反义词 / 词组各自折叠，中文跟着全局开关走。

### 发音

走浏览器自带的 Web Speech API（`speechSynthesis`），**不打包任何音频文件** ——
103 个词条各存一段 mp3 既占体积又难维护，朗读质量对背单词够用。
语速 0.88 放慢；iOS Safari 要求首次在用户手势里触发，所以由点 🔊 调用而不是加载时自动播。

### 单元简介是本应用写的

原书没有单元简介。`UNIT_INTROS` 里的 10 段是按各 Unit 的实际词条写的导读，
在代码和 `wordbooks.data.ts` 的注释里都写明了**不是书里的内容**，别当成原书引用。

### 顺手修掉的一个数据错误

下册「态度词」专题之前解析出 **54 条**，其中混进了例句的正文行 ——
例句内容被当成了同义替换条目。这一轮加了例句块边界之后变成 **25 条**，
逐条核对原文后确认 **25 才是对的**，54 是多的。

## 第七轮：Plan 页

### 一天一屏，左右滑动

原来周一到周日七张卡片竖着堆，要滚很久。现在一次只显示一天：

- 顶部七个 chip（一…日），直接显示当天 `完成数/总数`，点一下就跳过去。
- 中间卡片**左右滑动**翻页，到头有阻尼提示"没有下一屏"，不会硬推。
- 底部还有「前一天 / 后一天」，不用也得会滑。
- 打开时自动落在**今天**所在的那天；翻到别的周再回来也会回到今天。

### 任务右边的模块去掉了

任务行右侧原来写着「1 模块 / 2 模块」，真题任务写「30′ 考场」。
模块数对背单词的人没有任何帮助，真题该看的是考场时长而那在真题页的计时条上，
所以右侧整个腾空，改放**「去完成」**按钮（仅真题任务有）。

### + 自己加任务

每天卡片右上角一个 `+`，可以写任务名、备注、算几个模块。
自定义任务的 `origin` 记成 `"custom"` —— 调度器只会刷新 `origin === "generated"` 的
自动任务，所以自建的任务换档位、刷新周计划都不会被覆盖或删掉。
`verify.ts` 有断言守这条。

### 真题任务的「去完成」：两条路

```
听力 Section A+B  →  [去完成]
                      ├── 纸质版自己做  → 计时器 → 做完了，登记为已完成
                      └── 在 App 里做   → 直接跳真题页
```

纸质版不是二等公民，也是一条完整路径：

- **倒计时**默认用该 Part 的**官方考场时长**（听力 30 / 阅读 40 / 写作 30 / 翻译 30），
  超时后转珊瑚色并显示超时多久；随时可以**转正计时**不管它。
- 计时状态按任务 id 存在模块级，切面板不丢；只记真实用掉的秒数。
- 「做完了」点下去就是 `completeTask`，这一项正常计入当日完成、打卡和周统计。

### 今日打卡卡

当天任务全部做完（或跳过）之后，Weekly Load 卡上会出现「今天全做完了 · 发一张打卡」。

卡片用 **canvas 现画**（1080×1440），没有引 html2canvas / dom-to-image：
要的只是一张能发出去的图，那类库在移动端 Safari 上翻车概率很高。
卡上只写真实记录：做了哪几项、几个模块、连续几天、距考试几天、当前档位。

分享走 **Web Share API**（微信内置浏览器支持 `navigator.share`）。
带文件分享不一定被支持，所以探测 `navigator.canShare({ files })`，
不支持就退回「保存图片」+ 长按图片存 —— 这也是微信里最稳的转发姿势。

## 第八轮：词库的黄色高亮

### PDF 里的高亮不是文字属性

原书用**荧光笔**标重点，但 PDF 里高亮是 `/Highlight` 注解画的矩形，
文字层完全没有「这段被标了」的标记。所以光读 `.txt` 是读不出来的。

做法是 `scripts/extract-highlights.py`：用 `pypdf` 取注解的 `/QuadPoints`，
用 `pdfplumber` 取每个字符的包围盒，两边对上，落在矩形里的字符就是被标黄的。
两册一共挖出 255 处。

### 三道防错位闸

原书有些标黄压得很怪（高亮从 `the` 的 e 开始），所以加了三条规则：

1. **只收基本整个落在框里的字符**。按「中心点落在框内」筛会把前一个单词的尾巴
   吃进来 —— `innovation` 被读成 `l innovation`。
2. **匹配认词边界，并吸到完整的词上**。不加这条，一处独立标注的 `on`
   会命中 `innovati`+`on` 里的 `on`，把整张表标成错的。
3. **在这段文字里出现两次就不标**。说明撞了但对不上号，宁可漏标。

漏标的代价是多一条荧光笔；标错位置的代价是学生照着错的重点背。

结果：上册 17 处释义/词表标注、14 条例句高亮，下册 13 个同义替换重点词。
`verify.ts` 第 11 节守着不变量 —— `*HL` 分段拼回去必须等于同名纯文本字段。

### 例句变成同义替换题

书上标黄的例句位置几乎都是**同义替换点**：`tax cuts.` ↔ `减税`、
`argued` ↔ `认为`、`cult` ↔ `迷恋`。所以直接拿它出题：

> 挖掉标黄的那一段，给四个选项，其中一个正确、三个是**同一条同义链上的其他词**。

干扰项必须和答案形状一致（单词对单词、短语对短语）——
拿 `undergraduate` 当 `tax cuts` 的选项，猜中不难但也学不到东西。
正确答案的下标按题目 id 的散列打散，不固定在第一个。

## 第十轮：Study Journey —— 建议不是日程

### 定位变了

**面向大学生个人的独立备考平台。** 没有教师后台、班级管理、老师布置作业、教师实时干预。
所有学习建议与督学反馈都由系统独立完成。

第九轮那套「系统推荐 + 用户自定义 + 智能建议」在工程上是对的，
但它**在产品上是错的** —— 因为它仍然假设系统有资格排一张日程表，然后对学生考绩。
L1–L4 档位、每周时间预算、休息日、计划完成率，这四样东西合起来构成一套隐形的债：
学生一旦没照做，产品就有话可说，而学生最讨厌的恰恰是这个。

### 删掉的四样东西

| 删掉 | 原来在干什么 | 为什么删 |
| --- | --- | --- |
| `L1–L4` 档位 | 每周给一个固定的模块额度 | 档位是替学生决定「你每周该做多少」，而他连明天几点有空都不知道 |
| 每周时间预算 | 填了才能算超载 | 填一个时间预算就等于签下一张必须兑现的支票 |
| 休息日 | 让用户额外声明哪天不算 | 凭什么要用户为「哪天空着」再解释一次 |
| 计划完成率 | 排了多少做完多少 | 没有日程就没有分母，算出来的是自欺 |

替代品是**一条建议**：今天打开，系统给一项现在就能开始的事，做完记一笔，没做完也无所谓。

### 依据只有三种，且必须写出来

`WeeklyGoalItem.basis` 是硬要求 —— **推不出来依据的东西就不该推**。
依据按可信度分级：

1. **距考天数**（客观）—— 唯一完全客观的变量，来自档案里的考试日期
2. **真实练习覆盖度**（系统记的）—— 哪套卷的哪几段交过卷、写作翻译做过几次
3. **自评薄弱项**（学生说的）—— 只用来微调权重，**不决定阶段**

自报成绩（四级分 / 六级历史 / 目标分）**不参与任何分层**。
四级 550 分推不出六级 500 分，这条没有可靠依据，所以产品里不做任何六级分数预测。
`verify.ts` 对六个阶段逐个断言：依据非空、不含时间估算、不含分数预测。

### 阶段只看距考天数

`STAGES`：explore（没定考期）→ foundation（≥91 天）→ build（61–90）→
papers（31–60）→ sprint（8–30）→ final（0–7）。

阶段只决定**节奏**，不决定练什么。练什么由覆盖度和薄弱项说了算。

### 一张表记完所有练习

`StudyLog` 是全 App 唯一的「我做了 X」。五种 source 写同一张表：

```
focus        首页 Today's Focus
habit        Daily Habits（单词 / 精听）
practice     Practice 自主练习
weekly-goal  本周推荐目标里的一项
offsite      站外补录（图书馆、自习室、别的 App）
```

日历、连续天数、周报只读这一张表，所以「自主练习做了但统计没算」的重复计数从根上不存在。
`logStudy()` 是唯一写入口；带 `goalItemId` 时顺带把那一项标成完成 —— 一次动作，一条记录。

### 不积压

- Weekly Goals **不绑任何日期**，只有「这周建议做这几件事」
- 周末自然归档：没做完的直接带走，不结转、不显示「未完成 N 项」、不影响连续天数
- `WeekStat` / `MonthStat` 里**没有** `completion` 和 `plannedDays` 字段，`verify.ts` 断言它们不存在
- 日历里没记录的日子是空白的，不是红色的；界面上不出现「缺卡」两个字

### 学生永远有出口

首页只推**一项** Focus，给三个动作：开始训练 / 换一项 / 今天轻松学。
Plan 页给四种态度：整组接受 / 自己挑一项少掉 / 换内容 / 整组忽略 —— 系统推荐只是默认选项。

### 幂等：推荐绝不覆盖学生

`ensureWeeklyPlan()` 同一周重复调用返回同一份，学生删掉的项不会长回来，
自己加的项不会被刷掉。这是「系统推荐 + 用户自定义」在新模型下唯一还成立的形态。

> 这里修过一个真 bug：`getWeeklyPlan` 和 `ensureWeeklyPlan` 原来都用
> `where("weekStart").first()`，而忽略一份计划后同一周会存在两份（已归档 + 重新生成的），
> `.first()` 可能拿到已归档的那份，于是每次进页面都重新生成一份、把学生刚做的标记冲掉。
> 现在两处统一走「优先返回没归档的」。

### 旧数据怎么办

Dexie 升到 **v6**：删掉 `plans` / `tasks` / `rules` / `goals` 四张表并清空它们和 `logs`。
**保留 profile / settings / vocab / paperAttempts** ——
保留的是事实（你考了多少分、你攒了哪些生词、你做过哪套卷），清掉的是安排。
备份文件升到 v5。

### 校验方式

- `scripts/verify.ts` —— **3606 项**静态与纯函数校验（依据非空、无时间估算、
  阶段边界、统计口径、词库完整性、黄色高亮、听力四选项）
- `scripts/verify-plan-store.ts` —— **90 项**行为校验（`fake-indexeddb`）：
  幂等不覆盖、五种来源共用一张表、覆盖度只认事实、归档不结转、备份往返、薄弱项可空

## 推荐引擎的规矩

- **真题槽位指向真实题段 id**（`l-c1` / `r-c1` …），不是占位符。
  `verify.ts` 断言 `PRACTICE_UNITS` 里每个槽位绑定的题段在题库里真实存在，且生成的推荐确实指向它们。
- **每条建议都必须带依据**。`basis` 为空的建议不允许存在 —— 推不出来就不该推。
- **依据只来自三处**：距考天数（客观）、真实练习覆盖度（系统记的）、自评薄弱项（学生说的，只微调）。
  自报成绩不参与分层，也不换算成任何预测分。
- **覆盖度低的板块优先**，自评薄弱的**往前挪一位**（不是插队到最前）—— 但它永远不能决定阶段。
- **词汇永远垫底**：不是缺口就是习惯，不占真题槽位的位置。
- **推荐只在学生看过之前是"新的"**。一旦学生改过（删项、加项），`ensureWeeklyPlan()` 就不再动它 ——
  系统推荐只是默认选项，不是唯一的真相。
- **系统话术会重算**：标题那句和每条依据在打开这一周计划时按当前状态重算（第十九轮），
  所以「已练 0 篇」不会一直停在 0，也不会停在改版前的旧句式上。

## 界面语气

所有面向用户的句子集中在 `src/lib/copy.ts`，不在页面里各写一份。

### 底线四句

产品的立场，不随场景变化，也不跟歌词混着轮换。

| | 句子 | 出现在 |
|---|---|---|
| 分数 | 分数靠练，不靠换算和预测～ | 我的（成绩卡）、Journey（周回顾） |
| 隐私 | 数据只保存在这台设备上，不会上传到任何服务器。 | 我的、设置 |
| 习惯 | *And it's alright, it's okay. We will get another day. To begin again.* | 今天（**仅在今天已有记录时**）|
| 缺卡 | *We live and we learn to take one step at a time. There's no need to rush.* | 日历（点开某天、那天没记录）|

习惯与缺卡这两条本来就是立场，不适合写成标语，用歌词原句更轻。
它们不带中文旁注 —— 旁注是给场景陪伴用的，底线不需要被解释。

### 歌词陪伴

一句一个场景，不并列、不轮播堆叠：

| 场景 | 出处 | 出现在 |
|---|---|---|
| begin | Jordin Sparks · One Step at a Time | 欢迎页 |
| return | Ingrid Michaelson & ZAYN · To Begin Again | 今天（今天一条记录都没有） |
| weekly | Miley Cyrus · The Climb | Journey 周回顾（**仅当没做完**）|
| night | Tom Odell · Best Day Of My Life | 日历（**过去的月份**且整月没记录）|
| streak | Journey · Don't Stop Believin' | 今天（**连续满 3 天**且今天已有记录）|

三条排版/触发规矩：

1. **歌词只放在人已经累了的地方。** 用户有劲的时候不泼「没关系」。
2. **不加「加油」「别放弃」。** 歌词自己会说，加上去像家长 —— `verify.ts` 第 13 节会断言这两类词一次都不许出现。
3. **两句不能同时出现。** 例如今天没记录时，`return` 由「今天做了什么」那张卡接手，
   习惯底线就自动让位；`streak` 也要求今天已有记录，否则不触发。

每句都带署名。歌词是别人的东西，藏着不给等于偷。

### 核心词库：点单元必须进得去

翻卡这套东西写了很久，但**从来没有真的进得去**。

原因在 `WordbookBrowser`：`view` 一个 state 同时扛了两件事 ——
「现在看哪一册」和「有没有进单元」。早返回的条件写的是 `view === "cards"`，
可 `view` 只有那个两选项的分段器会写，而分段器只能写 `"units"` 和 `"topics"`。
于是 `"cards"` 永远写不进去，点单元只改了 `unitNo`，条件不成立，界面纹丝不动。

现在两件事分开：`book` 管册别，`unitNo` 管有没有进单元，判断只看后者。
这类 bug 组件测试测不到，`verify.ts` 第 15 节直接盯源码里那条条件。

同一层还有个假按钮：「上一个」「下一个」被 `disabled` 无条件写死了，
只能靠滑动或键盘翻。现在按边界禁用（首词禁上一个、末词禁下一个）。

### 发音：先挑对音色，再谈语速

早期版本的朗读「听着怪」，不是一个原因，是四个叠在一起：

1. **英式音标配美音朗读。** 词库标的是 `ɪ'kɒnəmɪ`、`'prɒfɪt`、`ˈsemɪnɑː(r)` —— 剑桥体系，
   全是英音。而代码里 `utterance.lang` 写死 `"en-US"`，学生看着英式音标、听着美音，
   对不上就只觉得「怪」。
2. **音色取列表第一个。** `getVoices()` 返回的列表里混着 macOS 的 novelty 彩蛋音色
   （Zarvox、Bubbles、Organ 那种）和早年机器 TWS，`find` 第一个经常正好挑到最差那个。
   现在改成打分排序：先排除已知劣质音色，再优先 Enhanced / Siri 之类的高品质音色。
3. **叠音。** 原来有个「350ms 后如果没在说话就再说一遍」的兜底，
   碰上语音列表晚加载就变成同一个词叠着说两遍。
4. **点了没声音。** Chrome 上 `cancel()` 紧接着 `speak()` 有已知的静默失败，
   引擎还没从上一次取消里恢复就吞掉这一句。现在让出一个事件循环再念。

**口音可切换**：设置页有「发音 · 英音 / 美音」，默认英音（跟词库音标一致），
并直接显示当前实际会用到的音色名 —— 听着不对时能立刻定位到是谁在念。
实测 macOS 上英音选到 Daniel、美音选到 Samantha。

口音和音色都要问浏览器要，服务端渲染时没有 `window` 和 `speechSynthesis`，
所以用 `useSyncExternalStore` 读（`getServerSnapshot` 给固定值），
而不是 `useState` + `useEffect` —— 后者既会水合不一致，也正是这套代码明令禁止的写法。

**没做在线 TTS。** 接云端发音音质确实更好，但那会把单词送出去，
和「数据只保存在这台设备上」这条底线直接冲突。发音留在了本机。

### 精简：界面不解释自己

第十二轮把解释性长句全删了。留下的只有标题、按钮、字段标签、状态、数据、依据、占位符，
外加上面的歌词和底线四句。

删掉的是这三类：

1. **解释产品机制** —— 「接受之后随时能改数量或换内容」「同一个词重复记会合并」
   「阶段只看离考试还有多久」。功能就在按钮和结果里，不用文字再讲一遍。
2. **自我辩解 / 数据库旁白** —— 「数据只存在这台设备上」「没有账号，也不联网」
   「全都是你自己填的」。隐私有底线四句兜底，页面上重复说反而像心虚。
3. **与按钮重复的引导** —— 「不喜欢就换一项」写在「换一项」按钮下面
   「练了点什么就点记一笔」写在「记一笔」旁边。按钮已经说清楚了。

顺带去掉了两处**同屏复读**：类型标签和标题说同一个词时只留一个
（`听力真题 听力真题` → `听力真题`），周报也不再说一遍卡片表头已经有的数字
（`weeklyFocus()` 不再输出建议数和阶段意图，见 `src/lib/journey.ts`）。

`verify.ts` 第 14 节把这件事钉住：14 条已删文案逐条锁死，
11 个界面文件不允许内联歌词或底线（改文案只有 `copy.ts` 一个出处）。

### 高亮：书里标黄的字，界面上也得看见

书上的黄色高亮是这本书最值钱的部分 —— 那等于编者替你标好了「这个词在这里
才是考点」。但这些标注在数据里躺了很久，一次都没被显示出来。

`src/components/vocab/marked.tsx` 里的 `Marker` / `MarkedText` / `MarkedLine`
早就写好了，`wordbooks.data.ts` 里也早就有 `meaningHL` / `termHL` / `sentenceHL` /
`translationHL` / `articleHL` / `questionHL` / `textHL` / `headwordHL` 八个字段 ——
零处引用。等于做了标记层、备好了数据，然后忘了接线。

现在全接上了：

| 位置 | 字段 | 界面上是什么 |
| --- | --- | --- |
| 词卡主释义 | `meaningHL` | 「危**机**」的「危机」标黄 |
| 右栏词条（近义/派生/词组/扩展） | `termHL` | 整条按原书样子标黄 |
| 右栏释义 | `senses[].meaningHL` | 释义里的关键词标黄 |
| **英文原句** | `sentenceHL` | 例句里的考点词标黄 |
| **中文提示答案句** | `translationHL` | 译文里对应位置标黄 |
| 下册文章 / 题干 / 选项 | `articleHL` / `questionHL` / `options[].textHL` | 同上 |

英文和中文标黄的位置是对应的 —— 英文里高亮 `inadequate.`，
中文译文里就正好是「危**机**」，一眼能对上。

有 `termHL` 的词条整条用 `Marker` 显示、不再套 `Chip`：
原书的语义就是一块黄底，Chip 的底色再叠一层黄会发脏。
没有 `termHL` 的才退回 `Chip`，保持界面外观统一。

**`headwordHL` 有意不渲染。** 单词卡当前这个词就是它，
例句区再写一遍「profit n. 利润」纯属重复。`verify.ts` 第 16 节对此写了**反向断言**，
免得以后有人「顺手补上」。

**改名：原书例句 / 真题例题 → 原题例句。** 界面上原来说「原书例句」，
但这些句子来自历年真题，不是书里自造的；「原书」指的是高亮标注来自书里，
两个意思混在一个词上会误导。现在上册下册统一叫「原题例句」，
带文章的例题在 hint 里标「含原题」。

`verify.ts` 第 16 节共 14 项：七类 HL 字段必须各自接到界面、
`marked.tsx` 必须被引用、`MarkedText` / `Marker` 不能被删掉、
外加 `headwordHL` 的反向断言。

## 第十七轮：砍掉两处、换掉两种交互、修一个颜色坑和一个真 bug

### 砍掉：建构期

阶段从五段变四段：

| 阶段 | 距考天数 |
| --- | --- |
| 打底期 FOUNDATION | 61–∞ |
| 真题期 PAPER PHASE | 31–61 |
| 冲刺期 SPRINT | 8–31 |
| 考前一周 FINAL WEEK | 0–8 |

**删中间一段最容易留的坑是空洞。** 原来打底期是 `from: 91, to: Infinity`，
建构期占着 61–91。直接删掉建构期而不动打底期，70 天的人就谁都不匹配，
`stageFor()` 一路掉到最后一个阶段，于是被判成「考前一周」。
所以打底期的下界必须一并放宽到 61，覆盖度目标也跟建构期那一档合并
（听力/阅读 7、写作/翻译 2 —— 合并前打底期只有 3/3/1/1，量会凭空掉一半）。

还有一处连带：`stageId` 是生成推荐那一刻**写进周计划**的，老库里可能存着已下线的
`build`。`plan/page.tsx` 原来认不出来就退回 `STAGES[0]`（「还没定考期」），
对一个定了考期的学生是驴唇不对马嘴。现在退回改成按当天距考天数重算。

### 砍掉：「多一项」

只加数量、不挑内容的那个入口删了，「加一项」（自己挑）和「少一项」（减数量）留着。

### 暗色模式：黄字配白底

计时器看不清不是配色没调好，是**用错了配对**。全站十处都是同一个写法：

```
bg-fg text-primary
```

暗色模式下 `--cet-fg` 是 `#f4f1e6`（近白），`--cet-primary` 是 `#dfff63`（荧光绿），
这俩撞在一起对比度约 **1.05 : 1** —— 等于没写。亮色模式下是深底配亮绿，所以一直没暴露。

反色 chip 正确该用的是 `bg-fg text-bg`（`--cet-bg` 恰好与 `--cet-fg` 相反），
这正是 `button.tsx` 的 `ink` 变体和底部导航一直在用的配对。十处全部换成它。

`verify.ts` 扫全部 76 个源文件禁掉这两种写法，以后谁写回去直接红。

### 选词填空：点空格填词，不是十张题卡

原来 2025-12-set1 的 Section A 是这样渲染的：**10 张题卡，每张带 15 个选项**
（选词填空的题卡本来就没有自己的 options，10 × 15 = 150 个按钮竖着摆下来）。

现在：

1. 原文里的空就是题面。点它选中 → 点词库里的选项填进去。
2. **再点一下已经填好的空 = 删掉它**，然后直接换别的。
3. 词库选项「只能用一次」是真的：往新空里填同一个键时，
   `placeAnswer()` 会先把它从原来那一空里摘掉，不会出现一个字母占着两个空。
4. 题卡整个不渲染了。交卷后给一张紧凑结果表（题号 / 对错 / 正确答案的词 / 解析）。

为此给作答记录补了两个动作：`clearAnswer()` 和 `placeAnswer()`。

### 记生词：改成在原文里点那个词

原来每道题底下挂一个「记生词」按钮，点开列一堆候选词让你挑。三个问题：

1. **选词是系统挑的。** 候选词靠 `wordsOf()` 的长度阈值 + 虚词黑名单猜，
   挑出来的多半不是「我刚才不认识的那个」。
2. **候选词来自选项，不是来自原文。** 听力那条链路喂的是
   `(q.options ?? []).flatMap(o => wordsOf(o.en))` —— 记的是选项里的词。
3. **每题一个入口。** 16 段的匹配题就是 16 个「记生词」按钮，把原文挤走了。

现在 `TappableText` 把原文里每个词做成真正的 `<button>`：点哪个词就收哪个词，
出处直指读到这个词的那一段。Section B 的按钮自然就没了 —— 不是单独删的，
是这套交互把它取代了。旧的 `words.ts` 猜测器一并回收。

代价是长文里 tab 停点很多，这是「每个词都能存」必然的代价；可点性用极淡的点线
下划线表示，按下去才上荧光黄。

### 顺带修掉的一个真 bug（不是这一轮引入的）

浏览器实测时撞到「距考试 0 天 · 考前一周」，而档案里明明是 62 天。

根因在 `useWeeklyPlan`：它只要「还没有计划」就调 `ensureWeeklyPlan()`，
不管档案存不存在。学生还没填完 onboarding 就先进了 `/plan`
（`useRequireProfile` 会把他弹去 `/welcome`，但 hook 的 effect 早就跑完了），
此刻 profile 还是 `undefined`，于是

```ts
examDate: profile?.examDate ?? todayKey()   // 「还没填考期」被算成「距考 0 天」
```

生成了一份 **考前一周** 的推荐并**存进库**。等学生填完考期回来，计划已经存在、
不再重算，于是「距考试 0 天 · 考前一周」就一直挂着，还按考前一周的标准量
（听力/阅读 14 段）去推荐题段 —— 同时违反「阶段只看距考天数」和「推荐必须可追溯」
两条底线。

现在 `useWeeklyPlan` 等档案就绪了才生成。`verify.ts` 第 18 节钉住这个顺序。

### 校验

`verify.ts` 新增第 17、18 两节：第 17 节管这轮砍掉的和换掉的（四段无空洞、
「多一项」没了、76 个文件无「近白底配荧光绿字」、全站无「记生词」、
`words.ts` 不许回来、选词填空必须按 `kind` 分开、必须用 `clearAnswer`/`placeAnswer`），
第 18 节管档案没就绪不许生成周计划。

## 第十八轮：词性不白给、标题全英文、音频能拖能变速

### 选词填空：做题时不给现成词性，学生自己标

上一轮把解析册的词性直接印在词库上（`A. adolescents n.`），还加了一排
`n. ×6 / v. ×3 / adj. ×3 / adv. ×3` 的分布按钮。方向错了：选词填空公认的第一步
就是**自己**给 15 个备选词标词性，题面一旦写好 n. / v.，第一步就白给了，
那排数字更是等于把答案的分布直接递过去。

现在两边彻底分开：

| | 词性从哪来 | 什么时候 |
| --- | --- | --- |
| 做题时 | 学生自己标的（`PaperAttempt.posMarks`） | 随时标，标错也能改 |
| 交卷后 | 解析册的 `bank[].pos` | 交卷才揭晓 |

- 词库每个词后面挂一个小圆圈：点它 → 上面弹出 `n. / v. / adj. / adv.` →
  标上，词后面就多一个黄底词性徽标（`--cet-marker`）。
- 分布按钮整排删掉 —— 那几个数字来自答案键，本身就是泄题。
- 标过的词性存进作答记录，刷新不丢；交卷后解析第一步会把
  「你自己标的也是 adv.，对上了」/「你自己标的是 v.，这个词是 n.」摆出来。
- 词性选项只有一处出处（`bank.ts` 的 `POS_ORDER`），界面里不许写死字面量。

### 题目标题一律英文，只留卷面名

- 听力题段：`Recording One`（不再是「Recording One · Why Luggage Gets Lost」）。
- 阅读题段：按题型给 `Banked Cloze` / `Matching` / `Reading Comprehension`，
  唯一出处是 `papers/index.ts` 的 `readingKindTitle()`。
- 试卷名 `CET-6 · Dec 2025 · Paper One`，真题库卡片和试卷页都用它。
- 写作 / 翻译：`Writing` / `Chinese to English`。
- 原来的中文标题（`labelZh`）留在数据里做对照，界面上一个字都不再出现。

### 音频：进度条能拖，倍速自己选

- 进度条从一根死的横条改成 `role="slider"`：点哪跳哪，按住能拖
  （`setPointerCapture`，手指滑出轨道也不断），左右键 ±5 秒、Shift ±15 秒。
- 倍速三档 `0.8× / 原速 / 1.5×`，直接改播放器的 `playbackRate`，播放途中改立刻生效。

### 顺手修掉的三个问题

1. **标词性会互相覆盖**（既有 bug）：`use-attempt.ts` 的 `update` 原来是
   「先 `get` 再 `put`」两个独立事务，两次改动挨得近时后一次读到的是旧记录，
   写回去就把前一次覆盖掉。现在整段放进一个读写事务。
2. **暗色模式：淡紫底压白字**：试卷页那张 `bg-lavender` 的分数卡没写文字色，
   暗色下继承到近白的 `text-fg`，浅紫底上几乎看不见。紫底一律配 `text-on-accent`
   墨字（`paper-header` / `practice` / 阅读段号 / 听力说话人徽章一起改）。
3. **答对了也说「错在后面两步」**：解析卡那句「你选的那个也是 adv.」没绑在答错上，
   答对时也冒出来。现在只在答错时说。

### 这轮删掉的文案

## 第十九轮：推荐依据重写、「少一项」自己挑、试卷里删掉翻页按钮

### 推荐依据：三种事实，三段句式

依据只有三种事实，按可信度从前往后排：距考天数（客观）、系统记的练习进度、
学生标的弱项（只做微调）。现在每一条都写成同一个句式：

> 距考 61 天，已练 0 篇。结合剩余备考时间，建议本周练习 7 篇。此项较为薄弱。

| 目标 | 依据 |
| --- | --- |
| 听力真题 | 距考 61 天，已练 0 篇。结合剩余备考时间，建议本周练习 7 篇。 |
| 写作一篇 | 距考 61 天，已练 0 次。结合剩余备考时间，建议本周练习 2 次。你标记为弱项。 |
| 阅读真题 | 距考 61 天，已练 0 段。结合剩余备考时间，建议本周练习 7 段。 |
| 翻译一段 | 距考 61 天，已练 0 次。结合剩余备考时间，建议本周练习 2 次。 |
| 核心词汇过一轮 | 距考 61 天，词汇尚未开始。结合剩余备考时间，建议过完一轮核心词汇。 |

规矩：

- **量词跟着板块走**：听力按「篇」，阅读按「段」，写作和翻译按「次」，词汇不按模块计。
- **建议量 = 这一阶段该练的 − 已经练过的**。练过 0 篇建议 7 篇，练过 3 篇就只剩 4 篇；
  练够了就写「这一阶段建议的 7 篇已经练够了，想练就多练」，不再硬凑一个数。
- **弱项尾巴最多一条，不叠加**：学生自己标过的写「你标记为弱项。」，
  没标过的那几块里练得最少的一块写「此项较为薄弱。」。没人标弱项时不会出现前者。
- **还没定考期**不编「距考 N 天」，写「还没定考期，暂不安排量。已练 0 篇，想练就练。」

「这周建议」卡片下面多一行总说明，依据弹层里也是同一句：

> 推荐依据：考试剩余天数、系统记录的真题练习进度、用户标记的弱项（仅做微调使用）。

### 存量计划的话术不再锁死

计划是存进 IndexedDB 的，生成那一刻写下的依据会一直躺在那儿 —— 改一版文案，
学生看到的还是旧句子；今天练了新题，「已练 0 篇」也永远是 0。

现在每次打开这一周的计划，都按当前状态把**系统话术**重算一遍：

- `journey.ts` 的 `recomputeBasis()` 和生成推荐走的是同一套规则，两处不会写出两样话。
- 标题那句「距考试 N 天 · 阶段名」一起重算（`planRationale()`），
  不会标题写 61 天、依据写 60 天。
- 只动话术：学生自己加的项、删掉的项、顺序、数量、已完成标记都不动。
- 算出来跟原来一样时**不写库**，所以打开页面不会反复写；写完之后 liveQuery 送回新计划，
  再算一次还是一样的，不会转圈。

### 自评弱项只往前挪一位

原来的排序给自评弱项减 0.6 分，结果是弱项直接插队到最前面 —— 那不叫微调。
现在改成：先按覆盖度排，然后弱项**往前挪一位**。所以 61 天、什么都没练、
标了写作弱项时，顺序是 听力 → 写作 → 阅读 → 翻译 → 单词。

### 「少一项」由学生自己挑

原来是 `resizeWeeklyGoals(plan.id, goals.length - 1)`：系统自己砍掉最后一项。
现在点「少一项」弹一个 Sheet，列出这一周的几项，学生点哪一项就少哪一项
（走 `removeWeeklyGoal` 精确删除）。`resizeWeeklyGoals` 整个删掉了 ——
那条路就是「系统自己少」，留着迟早有人用回去。

### 试卷内部不再摆翻页按钮

试卷页那一行原来是「第 16–18 题 · 本段 1/3 · 全 Part 1/7」加一对圆形左右按钮。
按钮删掉，只留文字：**翻页靠手势拖动、按方向键、或者上面的 Part / Section chip 直跳**。
真题页里能点的按钮太多，反而分不清哪个是题、哪个是控件。

### 校验

`verify.ts` 第 22 节盯这轮的东西：依据的句式（按量词分别匹配）、弱项尾巴最多一条、
没人标弱项时不出现「你标记为弱项」、自评弱项只挪一位、「推荐依据」那句在、
「少一项」不许再走数量截断、试卷内部不许再出现 `aria-label="上一段"` / `ChevronLeft`。

`verify-plan-store.ts` 第 2 节改成测「学生自己挑掉的那一项」，
新增第 16 节测「存量计划的话术会按当前状态重算，不会锁死在旧文案上」。

## 第二十轮：听力音频原来只播到第一题

### 现象

每一段听力，播放器都在**第一题**之后就停了。后面几题的题干永远听不到 ——
而做题界面按考场规矩又不显示题干（`hideStem`），于是那几道题既看不到也听不到。

### 根因不是播放器，是数据

音频文件本身没问题。对 35MB 的 MP3 做逐段能量分析 + 逐段转写核对后，
每段单元在音频里的真实构成是：

```text
原文/对话
  → "Questions N to M are based on …"
  → Question N（第一题题干）
  → 约 13.5s 答题停顿
  → Question N+1
  → 约 13.5s 答题停顿
  → …
```

当初做静音分析时，把「答题停顿的起点」当成了单元的终点，
于是 `window` 只切到第一题题干，而剩下的题干被放进一个叫 `dictationWindow` 的字段里 ——
**那个字段从头到尾没有任何代码读过**，是个死字段。题干就晾在那里没人播。

判断依据也写错过：注释里把停顿里那段英语题干记成了「报数字语音（约 3.5s）」，
以为应用会自己显示题干，所以不用播。实际转写出来是完整的英文题干。

### 改法

- `dictationWindow` 改名 `stemsWindow`，语义写清楚：**剩余题目的英文题干播报区间**，
  并把实测到的题号一起存进数据（`questions: [2, 3, 4]` 这样）。
- 新增 `unitAudioRange(unit)`：一个单元的完整可播区间 =
  `window.startSec → stemsWindow.endSec`。播放器只认这一个区间。
- 组件不再把 `unit.window` 直接喂给播放器。

改完每段的范围：

| 段 | 原来（只到第一题） | 现在（到最后一题的停顿结束） |
|---|---|---|
| l-c1 对话一 | 0:35 – 2:45 | 0:35 – 3:54 |
| l-c2 对话二 | 3:54 – 5:52 | 3:54 – 7:00 |
| l-b1 短文一 | 7:00 – 9:17 | 7:00 – 10:11 |
| l-b2 短文二 | 10:11 – 12:20 | 10:11 – 13:29 |
| l-r1 讲座一 | 13:29 – 16:42 | 13:29 – 17:33 |
| l-r2 讲座二 | 17:33 – 20:41 | 17:33 – 21:36 |
| l-r3 讲座三 | 21:36 – 24:29 | 21:36 – 25:40 |

7 段首尾相接不重不漏，可播总时长 **25:04**，落在考场听力 30 分钟之内
（这也从侧面印证了区间没错：真正的考场音频就是 25 分钟出头，题目之间留够答题停顿）。

### 校验

`verify-papers.ts` 新增：每段都要有 `stemsWindow`、题干窗口紧接原文结尾、
题干窗口的题号正好是本段除第一题外的全部题号、可播区间必须越过原文结尾、
7 段区间首尾相接、可播总时长不超考场听力时长。

`verify.ts` 第 23 节盯住代码层：组件必须用 `unitAudioRange()`、
不许再把 `unit.window` 直接喂给播放器、`dictationWindow` 这个死字段不许回来。

### 还没动的（留着等你定）

- **Section B / C 的 Directions 目前混在原文窗口里**（l-b1 开头是 "Section B Directions"，
  l-r1 同理），而 Section A 的 Directions 已经被排除在可播范围外 ——
  三段待遇不一致。考场上 Directions 本来就是念出来的，所以这不算错；
  要统一的话得再定一刀切在哪，而且一刀切之后 7 段之间就不再首尾相接了。
- **逐题重听还没做**。现在整段连着播，错过了某题可以用进度条拖回去；
  想要「单独重听第 3 题的题干」的话，需要把每个题干的起止时间也测出来存进数据。

## 第二十一轮：2024 年 6 月三级真题入库，顺手修掉一个把听力顺序搞反的 bug

### 进了什么

用户提供了 2024 年 6 月六级真题三套的卷面 PDF、答案速查 PDF，以及第 1、2 套的听力 MP3：

- 卷面：3 份，选项、阅读原文、写作题面、翻译中文原文
- 答案速查：3 份，答案、写作参考范文、翻译参考译文
- 录音：2 份（**第 3 套没有录音，而且这是官方就有的设定**）

第 3 套的卷面自己写着：「由于多题多卷，官方第三套真题的听力试题与第二套真题的一致，
只是选项顺序不同，因此，本套试卷不再提供听力部分。」答案速查里也**没有听力答案表**。
所以第三套只进阅读、写作、翻译，不硬造一套听力出来。

### 听力：题干不在卷面上，在录音里

2024 年起六级卷面的听力题**只印 A–D 选项，不印题干** —— 这一点是逐字排版核过的
（PDF 里 `1.A) Reply to the man's last proposal...`，`1.` 和 `A)` 之间没有任何字）。
题干只在录音里念出来。所以：

- 听力题的 `stem` 取自**录音的机器转写**（listen_audio），是录音里真实读过的那句话；
- 录音转写同时给出 `Question 1. What does the woman say she will do?` 这类播报，
  正好对上卷面 25 道题。

录音原文也是转写来的（没有解析册），文件头写明了这一点，不冒充人工听写。

### 音频窗口：实测 + 二分

答题停顿用同一套静音能量分析（20ms 帧 RMS、-46 dBFS、桥接 0.3s 间隙）检出，
第 1、2 套各 **25 个** 13.2–14.7 秒的停顿，分组 **4/4/3/4/3/3/4**，
与卷面「1-4 / 5-8 / 9-11 / 12-15 / 16-18 / 19-21 / 22-25」一题不差 —— 这是交叉验证。

第一段前面还有 50 多秒的 Section A Directions。为了和 2025.12 那一套保持一致
（那一套的单元窗口是从对话开始的），这段边界用**二分法实测**：
把 `[0, t]` 整段转写，看对话的第一句有没有出现，二分到 0.5 秒。不是估的。

### 解析：没有解析册怎么办

2024.06 **没有解析册**，只有「答案速查」（答案 + 参考范文 + 参考译文，没有逐题解析）。
所以逐题解析与原文依据句由本项目依据真题原文撰写，并且加了一道机械闸门：

> **每一条依据句都必须是这一套的转写 / 阅读原文的逐字子串**（归一空白后比较）。

这条断言写进了 `verify-papers.ts`，谁写解析谁过不了这关。选词填空那 10 题的解析
按「语法判断 / 语义判断」两段写，界面才拆得出「词性 → 语法 → 语境」三步。

词库的词性也是本项目按每个词**在原文里的实际用法**标注的（不是解析册原文），
这一点写在每套卷面的出处里：`sources.explain`。

### 顺手修掉：听力 Section 归属一直搞反了

老代码按题段标题的前缀猜 Section：`Recording→A`、`Conversation→B`、`Passage→C`。
但六级卷面实际是 **A = 两段对话（Q1–8）/ B = 两篇短文（Q9–15）/ C = 三段讲座（Q16–25）**。
猜反的直接后果：真题页的听力浏览顺序是 **Q16→Q1→Q9**，跟卷面完全对不上；
而且 chip 上会写着「Section A · News」，可那一段其实是讲座。

改法：Section 字母写进数据（`ListeningUnit.section`），导航只读数据；
标题前缀只用来显示这一段是什么类型。

### 出处写进数据

新增 `Paper.sources`：卷面 / 答案 / 解析 / 听力原文分别来自哪里，
真题页卷面上直接摊开给用户看。没有出处的解析等于来源不明。

### 校验

`verify-papers.ts` 从「只验一套卷子」改成「按卷遍历」：

- 官方答案表改成 `OFFICIAL_KEYS`，四套卷子各自的答案逐题比对
- **依据句必须是原文逐字子串**（听力对转写、选词填空对原文并含空标记、
  长篇匹配对答案段落、仔细阅读对 Passage 原文）
- 听力题干必须是问句（说明它来自录音而不是卷面）
- Section 字母必须与题型一致（对话→A、短文→B、讲座→C）
- 没有听力的卷子不许带音频信息、也不许有听力题
- 题量、段落标签连续性、词库 15 项、10 个空、范文开头与题目一致 —— 全部按数据推导，不再写死

`verify.ts` 第 24 节盯代码层：四套卷子在库、每套写明出处、
`nav.ts` 必须用 `unit.section` 而不能再靠标题前缀猜。

## 第二十二轮：一个 4KB 的 ID3 标签，让 Chrome 整个不播 2024-06 的听力

### 现象

第二十一轮把 2024-06 三套真题导进来之后，浏览器实测发现：**2024-06 的听力在浏览器里放不出声**。
点「播放本段」，进度条永远停在 0:53。2025-12 那一套用同一个播放器却是好的。

### 一层层排除

- 控制台没有报错，`el.play()` 没有 reject；
- 网络面板里媒体请求是 206，但**每次都在几毫秒内被中止**（`net::ERR_ABORTED`），
  没有一条像 2025-12 那样持续几秒的流式请求；
- 把 2025-12 的 MP3 临时换到 2024-06 的路径下 → **同一个页面立刻能播**。
  所以不是播放器代码、不是路由、不是缓存，是**文件本身**；
- 服务器侧也没问题：Range / Content-Range / Accept-Ranges 都正常，
  两份文件的响应头一模一样。

### 根因：ID3v2 标签

逐帧解析两份 MP3：

- **2025-12**：ID3v2 标签 6445 字节（LAME 写的 XMP），44.1 kHz / 192 kbps，帧链完整；
- **2024-06**：ID3v2 标签 4192 字节，里面 `TPE1` / `TPE2` 两个文本框的编码字节写的是
  **ISO-8859-1（0x00）**，实际塞的却是 **GBK 字节**（`BB AA D1 D0 …`）。

macOS 的 afconvert 能照样把整段解码出来，Chrome 却一收到媒体请求就放弃。

**把这段标签剥掉，同一个文件立刻能播。**

### 为什么不重编，只剥标签

- 重编（32 kHz → 44.1 kHz / 128 kbps）当然也行，但那是**在用户的原始录音上再叠一层有损编码**，
  而这份录音本来就只有 32 kHz；
- 剥标签是**零损失**的：音频帧一个字节没改。剥完的 MP3 解出来跟当时做静音分析的 WAV
  **逐字节相同** —— 说明它本来就是用户给的原始录音，不是二次编码；
- 剥完重跑一遍静音分析，**25 个答题停顿一个不差地落在原来的位置**
  （169.44 / 238.14 / 370.34 / … / 1647.54），数据里的时间窗口一个都不用动。

对照实验：同一份 WAV 编成 32 kHz / 96 kbps 的 LAME 文件也能播 ——
说明**跟采样率无关，就是那个标签的事**。

### 加一道机械闸门

新脚本 `scripts/verify-audio.ts`（31 项），把「浏览器能不能播」能机械判断的部分全钉死：

1. 音频文件在 `public/` 下；
2. ID3 标签结构完整、不越界；
3. **文本框声明的编码要和实际字节对得上** —— 声明 ISO-8859-1 就必须是 ASCII；
4. MPEG 帧链完整，一帧接一帧走到文件尾（尾部允许一个 128 字节的 ID3v1）；
5. **文件真实时长要盖得住数据里最后一个题段的结束时间**（数据说这段 1647.54 秒结束，文件就至少这么长）；
6. `durationSec` 与文件实测时长一致。

拿坏文件试过：闸门会报「声明 ISO-8859-1 但含非 ASCII 字节 0xbb」；好文件 31 项全过。

### 浏览器实测（真实文件）

- 深链页 `/papers/2024-06-set1/listening/l-c1`：0:53 起播，1.5× 播到 **3:24**（越过第一题干 2:49），
  走到本段末尾 **3:58** 自动归位回 **0:53**；
- 第 2 套：0:53 起播，进度正常（区间 0:53 – 3:59）；
- 卷面页 `/papers/2024-06-set1`：播放器同样正常推进。

### 顺带记一笔（都是实测踩出来的）

- `afconvert -f MPG3 -d .mp3` 在这台机器上编不出 MP3
  （`ExtAudioFileSetProperty ('cfmt') failed`），所以改用 lameenc，
  备选链路留在 `scripts/encode-listening-mp3.py`；
- Next.js 的 `next start` **只服务构建时已经在 `public/` 下的文件**，新建文件要重新 build 才发得出去，
  而改已有文件的内容立刻生效 —— 这两点本轮都实测过；
- 浏览器工具的单次调用往返可能有几十秒延迟，
  「点播放 → 马上读进度」会读得太早，**必须隔一段时间再读**，否则会把没播误判成播了。

## 验收自检

`npm run check` 覆盖：

- TypeScript 严格检查、ESLint
- **4125 项业务规则**：六个阶段的建议**依据非空**、依据不含时间估算、不含任何分数预测、
  四个考场时长与 Directions 一致、10 个练习槽位指向真实题段、阶段边界（91/90、61/60、31/30、8/7）、
  倒计时动态计算、**统计里不存在 `completion` / `plannedDays`**、学生自己加的目标标成 `student` 且不编造依据、
  25 道听力题四选项齐全（藏题干的前提）、生词重复记只合并不覆盖、
  **核心词库完整性**（第五轮）：每条词有释义与 Unit 归属、Unit 号连续、无重复词条、
  派生词里混不进例句用词、每个专题非空、**部首兼容字不许残留**、
  搜索与 Unit/专题筛选不串味、
  **例句不许串行**（译文必须以终止符收尾、出处必须以年份开头、原书例题必须有题干和 A–D 选项）、
  **词表中英对照率 > 80%**、**每个单元都有简介**、下册例句必须挂在包含它的同义替换上、
  **黄色高亮片段必须能拼回原文**（第八轮，标错位置比不标更糟）
- **1872 项真题数据校验**：题号连续、55 题答案与官方答案表逐题一致、每题解析非空壳、
  音频窗口在时长内且递增、**每段必须有题干播报窗口且紧接原文结尾**、
  **题干窗口的题号正好是本段除第一题外的全部题号**、**可播区间必须越过原文结尾**、
  **7 段可播区间首尾相接不重不漏**、**可播总时长不超考场听力时长**、
  原文 `[n]` 落在本单元、
  每题有真实定位句、原文句不携带未验证时间戳、听力题必须 4 选项 A–D、词库 15 项、
  段落 A–P 齐全、空位数与题量一致、范文开头与题目一致
- **31 项音频文件校验**（第二十二轮）：音频文件在 `public/` 下、
  **ID3 文本框声明的编码要和实际字节对得上**（声明 ISO-8859-1 就必须是 ASCII）、
  ID3 标签不越界、**MPEG 帧链完整**（一帧接一帧走到文件尾，尾部允许一个 ID3v1）、
  **文件真实时长盖得住数据里最后一个题段的结束时间**、`durationSec` 与实测时长一致
